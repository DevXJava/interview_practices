Most common and simple way

@RestController
public class OrderController {

    @Autowired
    private RestTemplate restTemplate;

    public String createOrder() {
        String paymentStatus = restTemplate.getForObject("http://payment-service/pay", String.class);
        return "Order created with payment status: " + paymentStatus;
    }
}
⚠️ RestTemplate is deprecated for reactive use. Use WebClient for newer projects.

Part of Spring Cloud

Cleaner and more maintainable

Built-in support for load balancing (via Ribbon or Spring Cloud LoadBalancer)

🔧 Example (Using FiegClient)

@FeignClient(name = "payment-service")
public interface PaymentClient {
    @GetMapping("/pay")
    String makePayment();
}

@RestController
public class OrderController {
    @Autowired
    private PaymentClient paymentClient;

    @GetMapping("/create-order")
    public String createOrder() {
        String paymentStatus = paymentClient.makePayment();
        return "Order created with payment status: " + paymentStatus;
    }
}

High-performance alternative to REST

Useful for internal microservice communication

Day 25: Java Internals — What is the String Pool?

In Java, memory efficiency is key — and the String Pool is one of the most elegant optimizations built into the JVM.


🔹 What is the String Pool?

✅The String Pool is a special memory region inside the Java Heap where string literals are stored and reused to save memory.

✅When you create a string like this:

String s1 = "Java";
String s2 = "Java";

✅Both s1 and s2 point to the same object in the pool.


🔸 What if you use new?

✅String s3 = new String("Java");

✅This creates a new object in the heap, even if an identical literal already exists in the pool.


🔹 Use intern() to help reuse:

String s4 = new String("Java").intern();

Now s4 points to the string in the pool — not the one on the heap.


🧠 Why it matters:

1️⃣ Reduces memory footprint

2️⃣ Makes string comparison with == possible in some cases

3️⃣ Essential to understand for Java performance optimization and interviews

Object creation
Configuration
Wiring dependencies
Lifecycle management

Constructor Injection

| Concept                        | Description                                                                                |

Ensuring nothing breaks after deploying a microservice is critical for maintaining system reliability. Here’s a practical and professional approach that many teams follow — including techniques from CI/CD, testing, and monitoring:

✅ 1. Automated Tests Before Deployment
Run comprehensive tests as part of the CI pipeline:
Unit Tests: Validate individual classes/methods.
Integration Tests: Ensure the microservice works with its dependencies (e.g., DB, other services).
Contract Tests (e.g., using Pact): Ensure APIs work as expected for consumers.

End-to-End Tests: Run full workflows that touch multiple microservices.

✅ 2. Staging Environment Validation
Deploy to a staging or UAT environment first, which mimics production. Run smoke tests or automated regression tests there.

✅ 3. Canary Deployment / Blue-Green Deployment
Use safe rollout strategies:
Canary: Release to a small subset of users first. Monitor for issues.
Blue-Green: Run both old (blue) and new (green) versions in parallel, switch traffic only if green is stable.

✅ 4. Health Checks
Ensure readiness and liveness probes are defined:

livenessProbe:
  httpGet:
    path: /actuator/health
    port: 8080
Helps detect whether your service is healthy and can accept traffic.

✅ 5. Logging & Monitoring
Use observability tools to detect issues early:
Logging: Use centralized logging (e.g., ELK stack, Loki).
Monitoring: Use Prometheus, Grafana to monitor metrics (CPU, latency, error rate).
Tracing: Use OpenTelemetry/Jaeger to trace inter-service calls.

✅ 6. Alerting
Set up alerts for anomalies:
High response times
Increased error rates (HTTP 500s)
Circuit breaker open state (if using resilience libraries like Resilience4j)

✅ 7. Post-Deployment Smoke Test
Once deployed:
Call critical endpoints manually or via automated scripts.
Verify expected behavior — can users log in, submit forms, view data, etc.?

✅ 8. Rollbacks
Have a quick rollback plan in place via:
Versioned Docker images
Helm/Kubernetes rollout history
Infrastructure as Code for reverting changes

Day 25: Java Internals — What is the String Pool?

In Java, memory efficiency is key — and the String Pool is one of the most elegant optimizations built into the JVM.


🔹 What is the String Pool?

✅The String Pool is a special memory region inside the Java Heap where string literals are stored and reused to save memory.

✅When you create a string like this:

String s1 = "Java";
String s2 = "Java";

✅Both s1 and s2 point to the same object in the pool.


🔸 What if you use new?

✅String s3 = new String("Java");

✅This creates a new object in the heap, even if an identical literal already exists in the pool.


🔹 Use intern() to help reuse:

String s4 = new String("Java").intern();

Now s4 points to the string in the pool — not the one on the heap.


🧠 Why it matters:

1️⃣ Reduces memory footprint

2️⃣ Makes string comparison with == possible in some cases

3️⃣ Essential to understand for Java performance optimization and interviews
